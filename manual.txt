  Preamble
  --------


  This extension was designed from the ground up using native DirectSound
  technology to be the definitive Game Maker 8.2 game audio solution.
  
  While not as powerful as 8.2 Sound, this extension is much smaller and
  faster, using up only about 130 KB of exe space when compared to FmodEx's
  vast nearly 1 megabyte, with much less code running per frame and per
  function call, leading to better game size, load times and performance.
  
  Additionally, just like how it's done in the 8.2 Audio extension, in-memory
  sound resource handling allows for builtin sound organization in the 8.2 IDE,
  while also negating the long load times associated with loading sounds from
  disk at game start. Unlike the Audio extension, the DirectSound mixer
  produces fine quality audio mixing, without any glitches or hiccups.
  
  Finally, we've added even more quality of life features, such as the concept
  of persistent sounds, the ability to rename sounds, clearer error messages,
  configurable extension behavior, and other goodies from Sound and Audio such
  as .wasd sound packs, adding sounds from included files, referring to sounds
  as either strings or indexes, music layering and fading tools, and much more.
  
  The following file formats are currently supported:
  
    - WAV
        -> 8-bit and 16-bit PCM formats are supported.
        -> 24-bit and compressed WaveExt codecs are not supported.
    
    - OGG
        -> Vorbis game audio codec is supported.
        -> the Opus voice codec is not supported.
    
    - MP3
        -> vbr and cbr codecs up to 320kbps are supported.
        -> the newer v0 codec is not supported.
    
    - Tracker formats
        -> MOD, IT, XM, and S3M files are supported.

  Settings
  --------


- sound_global_volume
    Changes the master volume level. By default, it's set to 0.7, for a more
    comfortable listening experience. We do not recommend going above that, as
    game sound efects are usually mastered to 0.0db which is quite loud. You
    can use the sound_kind_volume function to allow the player to individually
    control the volume of sound effects and music.


- sound_settings(setting,value)
    The builtin audio engine in Game Maker is full of strange quirks.
    This extension has been designed to have a more standard behavior suited
    to a modern development environment. However, if your project has legacy
    code that relies on the vanilla quirks, you can disable one or more of
    these options to emulate the old Game Maker 8 behavior.
    
    By default, all of these options are enabled.
    
  - dsound_use_linear_volume
      Game Maker's volume scale is a logarithmic attenuation value, from 30
      to 100, where half loudness is somewhere around 85, and 60 is inaudible.
      This extension instead uses a more intuitive linear volume scale where
      50 is half as loud, and 0 is inaudible. If your project uses logarithmic
      volume, you can disable this option to restore the vanilla volume scale.
      Note that the volume value from the slider in the sound resource window
      is always logarithmic.

  - dsound_use_scheduler
      Game maker sound functions act immediately upon call. Sometimes this is
      undesirable, such as legacy code that plays a sound and then changes the
      volume - if your game is even a little laggy, you could hear a spike as
      the sound plays at full volume for a short time. Moreover, instances may
      finish playing between a sound_exists call and some code that actually
      does something to them, so your code had to handle that case. In order
      to mitigate such problems, this extension uses a scheduler system where
      newly played sounds and changes to sound instances happen simultaneously
      at the end of a step, in a more consistent and predictable way.
      Turning this option off will instead use immediate mode, where operations
      on sounds apply instantly when the functions are called. You can also
      selectively turn this off - for example, when doing a deadlock loop for
      loading screens - and then turn it back on again afterwards.

  - dsound_reuse_sound_ids
      Game Maker assigns incrementing ids to newly added sounds, but this
      means you will eventually run out of space for sounds at 100000 where
      this extension's instance ids start.
      Here we provide an option to reuse dead sound indexes for newly added
      resources. If your legacy code is not designed to handle that, you can
      disable this option to use incrementing ids only and leave deleted sounds
      permanently deleted.

  - dsound_respect_persistence
      Game Maker allows all sounds to keep playing between room changes. Our
      extension instead only allows sounds marked as 'persistent' to continue
      playing once the room changes. Disabling this option will allow all
      sounds to continue playing between rooms again.

  Managing resources
  ------------------


    Just like in the Audio extension, it is possible to use sounds added via
    the 8.2 IDE in your games. In functions, sounds can be referred to either
    via their sound resource index, or a string name. Additionally, it is
    possible to change the name of sounds for organizational purposes.


- sound_add(fname, kind, preload)
    Adds a sound from a file. Kind is one of the kind_ constants. More
    information on kinds is available in the sections below. Note that the
    preload option is only provided for compatibility and is currently ignored.


- sound_add_ext(fname,kind,name,vol,pan,pitch,persistent)
    Convenience function. Adds a sound, and sets all the properties on it.


- sound_add_directory

- sound_add_included

- sound_add_included_ext

- sound_exists

- sound_get_name

- sound_set_name

- sound_discard

- sound_restore

- sound_replace

- sound_delete

- sound_set_search_directory(dir)
    Originally, this function was used to tell Game Maker where to look for
    extra files required by a legacy DirectMusic file format.
    In this extension, this function is instead used to change the directory
    where the various sound_add functions will look for files when using
    relative file paths. Setting it to an empty string will let the system use
    the current working_directory when searching.

  Instance Management
  -------------------


    This extension allows for individual instances of playing sounds to be
    controlled. All functions that play sounds return an instance id that can
    then be used in the other functions.
    
    Please keep in mind that a maximum of 100 instances of each sound kind can
    be playing at a time. When attempting to play more than 100 sounds, the
    oldest instance of that kind will be destroyed to free up space.


- sound_play
    Plays a sound, and returns an instance id.


- sound_play_ext

- sound_play_single

- sound_loop

- sound_loop_ext

  Background Music
  ----------------


    We provide some convenience functions to make managing background music
    a little easier. Additionally, it is possible to have more than one layer
    of background music playing simultaneously, using the layer functions.


- sound_background_instance()
    Returns the instance id of the currently playing background music,
    or noone if there isn't one. If there are multiple layers of music
    currently active, the function returns the newest one.
    To get a list of all active background music layers,
    use sound_kind_instance_list(kind_background).


- sound_background_tempo(value)
    This function is not currently available due to no MIDI support, and
    instead shims sound_kind_pitch for the kind_background.


- sound_background_crossfade(index,time,volume,pan,pitch,loop)
    Crossfades between two background music tracks over a specified time.


- sound_background_switch(index,time,volume,pan,pitch,loop)
    Fades out the current background music then fades in the new one.


- sound_background_layer(index,vol,pitch,pan,loop)
    Adds a new layer of background music.


-------------------------------------------------------------------------------

  Sound Persistence
  -----------------


    In order to solve the common problem of looping sounds remaining after
    leaving a room, we have a new sound persistence system. Only sounds that
    have the persistent flag are allowed to continue playing between rooms.

  
- sound_set_persistent(index,persistent)
    Makes a sound index or instance persistent. When a sound is persistent,
    all instances created from that sound will be persistent too.

  Getters and Setters
  -------------------


    All getters and setters accept either sound resources or instance ids.
    Any sound-only properties, when queried on instances, will instead return
    the property for the sound resource of which it is an instance of - for
    example, instances do not have a 'preload' attribute.
    
    
    Additionally, a different method is used to calculate the mixing properties
    of instances. Usually, when you change the volume or pitch value of a sound
    resource, any changes to an instance of that sound would simply override
    those settings.
    To mitigate this, instance properties are now combined with those of the
    sound resource of which it is an instance of, as well as the settings for
    the 'kind' of the sound, and the master volume value.
    
    For example, if a sound resource has the following properties:
    
    - volume:  0.50
    - pitch:   0.90
    - pan:     0.10
    
    and the kind of the sound is set to the following:
    
    - volume:  0.75
    - pitch:   1.00
    - pan:     0.00
    
    and the instance has the following properties:
    
    - volume:  0.80
    - pitch:   0.50
    - pan:     0.30
    
    and the master volume is 0.70, then the resulting sound coming out of the
    mixer would be:
    
    - volume: 0.21 =  0.50 * 0.75 * 0.80 * 0.70
    - pitch:  0.45 =  0.90 * 1.00 * 0.50
    - pan:    0.40 =  0.10 + 0.00 + 0.30
    
    This system allows for developers to set base values on a sound resource
    for mastering purposes, and then have each instance of that sound behave
    in a predictable way without having to go around and change values
    everywhere in your code.
    
    The overall programming experience is much more intuitive and convenient.
    
    
    Functions that take a unit_ type constant accept the following values:
    
    - unit_unitary
        A value from 0 to 1, representing the entire sound from 0% to 100%.
    
    - unit_seconds
        A value in seconds. For example, 194.159 represents 3m 14s 159ms.
    
    - unit_samples
        A value in samples. For a 44100hz sound file, 88200 is 2 seconds in.


- sound_get_frequency(index)
    Returns the frequency in hz of a sound file.
    Most commonly, files are either 44100hz or 48000hz.


- sound_get_kind(index)
    Returns the kind of a sound, as represented by the kind_ constants.


- sound_get_length(index,unit)
    Returns the length of a sound, in the specified unit.
    Note that this function does not accept unit_unitary, as that would always
    resolve to a value of 1.


- sound_get_volume(index)
    Returns the volume value of the sound or instance.


- sound_get_pan(index)
    Returns the pan value of the sound or instance.


- sound_get_pitch(index)
    Returns the pitch value of the sound or instance.


- sound_get_max_pitch(index)
    Returns the maximum allowed pitch value for a sound.
    Usually, this will be 200000 divided by the sound's sample rate,
    but it may vary by system.


- sound_get_pos(index,unit)

- sound_get_preload(index)
    Returns the preload flag of the sound resource, as set in the IDE.


- sound_volume(index,vol)
    Sets the volume value of the sound or instance.
    Volume cannot be negative or greater than 1.


- sound_pan(index,pan)
    Sets the pan value of the sound or instance.
    Pan is a value from -1 to 1, where -1 is left and 1 is right.


- sound_pitch(index,pitch)
    Sets the pitch value of the sound or instance.
    Pitch is a value from 0 to the maximum allowed for that sound.
    You can retrieve the maximum pitch value with sound_get_max_pitch.


- sound_fade

- sound_set_pos

- sound_set_loop(index,start,end,count,unit)
    Defines the start and end loop points for a sound or instance.
    Count defines how many times a sound loops before continuing from the end
    point. Set count to 0 to loop indefinitely.


- sound_set_properties(index,vol,pitch,pan,persistent)
    Shortcut to set all properties of a sound at once.

  Sound Kinds
  -----------


    Game Maker defines four basic sound 'kinds' that are used to determine the
    behavior of instances created from them. Here's a list of all the
    available sound kinds and how they are handled by the extension.
    
    kind_sounds (0):
        Normal sound effects. Any amount of instances can be created from
        them, and they cannot be used with the 3D sound functions.
  
    kind_background (1):
        Background music. Normally, only one instance of background music
        can be playing at a time, although we provide functions to layer
        more tracks.
    
    kind_3dsounds (2):
        Sounds that use a world position, velocity, and some extra properties
        to calculate doppler effects and cone occlusion models.
    
    kind_multimedia (3):
        Sounds that Game Maker cannot normally play, such as MP3 or WMA, which
        get piped into a Windows Media Player endpoint for playback. This
        extension does not need to do that, so this kind is handled the same
        way as kind_background (1), with only one instance allowed at a time.
    
    For the developer's organizational convenience, we also provide four extra
    kinds, labelled kind_extra1 through 4. Those new kinds occupy the indices
    4 through 7 and behave the same way as kind_sounds (0).

  Kind Functions
  --------------


    Same as the two previous sound extensions, it is possible to batch-operate
    on all sounds of a specific kind. For example, you may want to stop all
    kind_sounds, or change the volume of all kind_background music tracks.


- sound_kind_volume(kind,volume)

- sound_kind_pan(kind,pan)

- sound_kind_pitch(kind,pitch)

- sound_kind_pause(kind)

- sound_kind_resume(kind)

- sound_kind_stop(kind)
    Stops all sounds of a specific kind.


- sound_kind_instance_list
    Returns a ds_list with the instance ids of all active sounds of a kind.
    Make sure to delete the ds_list after you're done with it.

  Final Words
  -----------


  On Effects

    While effects seem difficult to implement, we do have plans to look into
    it. Some effects are achievable with the current setup, but the results
    are largely unattractive. Documentation for the DirectMusic SDK is hard to
    find, so we're not making any promises here, but it is theoretically
    possible.


  On Preloading

    Same as the Audio extension, all sounds are fully decoded to raw PCM data
    in memory when loaded. While most games don't have that much music in them,
    if this proves to be a problem, we plan to look into only loading sounds
    when they are first referenced, which would incur a small penalty on play,
    but would also allow for proper usage of the preload flag, sound_discard
    and sound_restore. Maybe this could also come as a config option.


  On Midi Support
  
    No promises, but we will probably look into it at the same time that
    effects are looked into since they use the same fundamental backend.


  We'll see how it goes.
